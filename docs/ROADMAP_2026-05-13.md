# AIMDNET 향후 진행 계획 — 2026-05-13

## 우선순위 A: 운영 안정화

### A1. 인증 보안 강화

- 현재 일부 구인·구직 API는 클라이언트에서 전달한 `userId` 또는 `license`를 기반으로 동작한다.
- 다음 단계에서는 서버 세션/쿠키 기반 인증 검증을 모든 API에 적용한다.
- API별 권한 정책을 명확히 분리한다.
  - 일반 사용자: 구직 프로필 관리, 추천 조회
  - 병원 원장/관리자: 공고 등록/수정/마감, 후보 추천 조회
  - 관리자: 사용자/공고 모니터링

### A2. 개인정보 및 민감정보 운영정책 보강

- 구인·구직 프로필 데이터에 대한 별도 보관 기간 및 삭제 정책을 정한다.
- 지원/연락 기능 추가 전, 개인정보 제3자 제공 또는 전달 고지 문구를 검토한다.
- 환자정보 입력 제한 문구는 서비스 전체에서 일관되게 노출한다.

### A3. 로깅/오류 모니터링

- Vercel 로그만으로 부족한 API 오류 추적을 보완한다.
- 주요 API 실패율, 평균 응답시간, 외부 API fallback 비율을 기록한다.
- 약제 검색, AI 질문, 지도 경로 계산, 회원가입 API를 우선 모니터링 대상으로 둔다.

## 우선순위 B: 구인·구직 기능 고도화

### B1. 실사용 워크플로우 추가

- `지원하기`
- `병원에 문의하기`
- `관심 공고 저장`
- `후보 저장`
- `공고 수정/마감`
- `매칭 제외/숨기기`
- 병원과 구직자 간 연락 기록 관리

### B2. 병원 원장 판별 개선

- 현재는 `jobTitle`과 `hospitalName` 기반 텍스트 판별이다.
- 장기적으로는 회원가입 단계에서 역할을 명확히 수집한다.
  - 봉직의/전문의/전공의/간호사/약사/병원 원장/관리자 등
- 병원 원장/관리자 권한은 요양기관번호, 사업자등록 정보, 관리자 승인 등으로 보강한다.

### B3. 매칭 알고리즘 개선

- 거리/시간/급여/근무형태/전문과목 가중치를 사용자별로 학습한다.
- 지원/저장/숨김 행동을 반영해 추천 품질을 개선한다.
- 공고와 후보의 필수 조건과 선호 조건을 분리한다.
- 매칭 사유를 더 자연어 설명 형태로 개선한다.

### B4. 지도/교통 API 고도화

- 네이버 Geocoding과 Directions는 유지한다.
- 대중교통 정확도를 높이기 위해 추가 API를 검토한다.
  - Kakao Mobility/Map API
  - Google Directions/Distance Matrix
  - 공공 교통 API
- 동일 주소 반복 조회를 줄이기 위해 좌표와 경로 결과 캐싱을 추가한다.
- 사용자 위치 설정 UI에서 주소 검색 자동완성을 추가한다.

## 우선순위 C: 약제 데이터 품질 고도화

### C1. 약제 원천 데이터 병합 안정화

- 공공 API dump, HIRA, MFDS, DUR 데이터를 병합하는 스크립트를 정리한다.
- 대량 dump 파일은 Git에 넣지 않고 외부 스토리지 또는 재생성 가능한 배치로 관리한다.
- `publicApiDump` 원본 JSON은 필요한 요약 필드만 DB에 남기는 방향으로 축소한다.

### C2. 약제 상세 품질 검증 자동화

- 약제 상세 핵심 필드 누락률을 정기적으로 측정한다.
- 이미지, 성분명, 효능효과, 용법용량, DUR, 급여여부, 상한금액 필드별 커버리지를 리포트한다.
- `quality:audit-drug-detail` 결과를 릴리즈 전 확인 절차로 둔다.

### C3. 검색 품질 개선

- 한글/영문 성분명, 제품명, 보험코드, 표준코드, 회사명 검색 정확도를 높인다.
- 자주 검색되는 약제는 캐시 또는 사전 인덱스를 적용한다.
- 사용자가 입력한 오타/부분어 검색을 보완한다.

## 우선순위 D: AI 기능 고도화

### D1. 의료 답변 안전성 강화

- AI 답변 상단/하단에 참고용 안내를 일관되게 제공한다.
- 진단/처방 확정 표현을 제한한다.
- 환자 개인정보 입력 제한을 프롬프트와 UI 양쪽에 반영한다.

### D2. RAG 품질 개선

- 약제 DB에서 가져오는 컨텍스트를 질문 유형별로 다르게 구성한다.
- DUR, 성분, 상호작용, 용법용량, 급여정보를 분리해 근거를 제시한다.
- 너무 많은 문맥으로 응답이 느려지지 않도록 top-k와 필드 크기를 제한한다.

### D3. 의료진 업무 기능 확장

- 환자 설명문 쉬운 말 변환
- 복약지도 문안 생성
- 영문/다국어 안내문 생성
- 진료기록 요약
- 동의서/안내문 템플릿 생성

## 배포 원칙

- 코드 변경 후 `npm run build`로 검증한다.
- DB 스키마 변경이 있으면 `npx prisma db push` 또는 마이그레이션 절차를 먼저 검토한다.
- 운영 배포는 `npx vercel deploy --prod`로 진행한다.
- API 키와 비밀값은 Git에 커밋하지 않고 Vercel 환경변수로만 관리한다.
